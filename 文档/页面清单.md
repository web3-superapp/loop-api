> 版本 v1.4 · 2026-08-23 · 基线：现有原型 11 屏 + 群内语音房模块
>
> **已拍板前置决策：**
> 1. 交易形态：**路线 C（多链现货 + Hyperliquid 永续双形态）**
> 2. 开发语言：**Flutter**
> 3. 交付路径：**直接开发 Flutter 客户端 + BFF + 自动化测试**；HTML 仅作已验收的交互/契约参考
> 4. 当前开发范围：先完成 A 档并建立可扩展到 B/C 档的生产工程，不再等待 HTML 全量定稿
> 5. Perp 入口：**Market 内分「现货 / 合约」两栏**，不加 Tab，6 Tab 不变
> 6. Chat 形态：**不做 Server/频道/角色权限**，保持会话列表 + 群聊 + 群内语音房
> 7. Perp 范围：**只做 Hyperliquid 核心白名单市场，不做 HIP-3 自建市场**
> 8. 安全层：**去掉「AI」包装，保留钱包基础安全能力**（详见下方第六节）
> 9. 实现策略：**集成优先**。每个模块先审计官方/成熟供应商能力；能由 SDK、API 或托管流程覆盖的只做薄适配层，LOOP 只自研差异化体验、编排与策略。确认存在供应商缺口后，任何自建基础设施都要单独说明成本/风险并再次批准
> 10. 通信目标：Flutter App 统一接 **Agora Chat + RTC（声网）**；历史 HTML 中的 Stream 只作交互参考，禁止双接

这份清单是测试用例、开发进度表、外包工作量估算的**共同地基**。任何一屏的增删都要回到这里改，不要在别的文档里另起一份。

## 一、编号与口径

| 概念 | 定义 | 计数方式 |
|---|---|---|
| **页（Screen）** | 一个独立可导航的视图，有自己的路由 hash | 计 1 |
| **弹层（Sheet/Dialog）** | 覆盖在页之上、不改变路由层级的面板 | 计 1（标注 `弹层`） |
| **状态变体（State）** | 同一页的空/加载/错误/成功态 | **不单独计数**，写在该页的「关键状态」列 |

**优先级三档**（决定 Flutter/BFF 的实现顺序）：

| 档 | 含义 | 当前 Flutter 实现顺序 |
|---|---|---|
| **A** | 砍掉闭环就断，或首次使用必经 | P0：先实现并形成端到端测试 |
| **B** | Phase 1 完整交付需要，但不阻塞闭环演示 | P1：在核心集成稳定后补齐 |
| **C** | Phase 2 能力，一期只占位 | P2：保留路由与供应商边界，不阻塞内测 |

**状态列**沿用历史 HTML 盘点口径：`已有` = 参考原型已实现；`扩` = 参考页需映射到 Flutter；`新` = Flutter 全新页。它不表示生产代码已完成。

## 三、路由结构

底部 6 Tab 不变（决策 5）：

```text
Tab 层    home │ market │ launchpad │ chat │ wallet │ profile
                   │
          ┌────────┴────────┐
       现货分栏          合约分栏 ← Perp 12 屏挂在这里
```

当前原型的 `ROUTES` 已是集中式多级数据表，Task 1 固定的 canonical stacks 为：`#send` = `wallet → send`、`#send-to` = `wallet → send → send-to`、`#send-confirm` = `wallet → send → send-to → send-confirm`、`#tx-result` = `wallet → tx-result`。F11 是覆盖在当前来源栈上的唯一共享弹层，F5 进入 F11 时仍保留完整 `wallet → send → send-to → send-confirm` 来源；F12 是独立结果入口而不是 F5 的可伪造尾节点。四个新路由目前仍是不可用结构壳，F3–F5/F12 功能待实现。

**路由不变量（沿用已拍板的工程纪律）**：hash / history / 内存栈由一处派生；App 内返回沿层级上一级，浏览器返回按真实路径回溯；非活动页 `inert` + `aria-hidden`。

## 四、剩余未决风险

> 原「Perp 让产品定性变了」一节已由决策 7、8 解决：perp 只做核心白名单市场（那里确实没有合约风险，所以不装安全层），现货侧保留钱包基础安全能力但去掉 AI 叙事。定性问题因此消失——产品不再声称"AI 帮你避开土狗"，而是"一个安全习惯良好的钱包 + 社交 + 双形态交易"。

### Chat 已收窄，但冷启动策略仍未定

决策 6 把 Chat 从 21 屏压回 13 屏，避免了在网络效应未验证前的过度投入。但原方案第八章风险 1（Chat 是闭环最弱一环，用户的人都在 Telegram）和风险 2（Telegram Bot 已满足"聊天里直接买"）**都还没有答案**。

清单不解决这个问题，只是把它的成本降到了可控。真正的答案在"是否先做 Telegram Bot 验证"这个待拍板项上。

## 五、安全层的新边界（决策 8）

**原则：保留能力，去掉叙事。** 不再说"AI 安全层"、不显示"AI 风险分 72/100"、不做 AI Guard 品牌包装，但钱包该有的安全义务一项不少——这些是 Rabby / MetaMask / Phantom 都有的基本功能，删掉会形成用户可感知的安全缺陷。

### 保留（改为朴素表达）

| 能力 | 原表述 | 改为 | 落点 |
|---|---|---|---|
| 无限授权拦截 | "AI Guard 拦截" | "This app is asking for unlimited access" + 限额建议 | F16 |
| 交易前模拟 | "AI 预检通过" | "Simulated — you will receive ≈ X" | F11、F7 |
| 地址风险校验 | "AI 检测到高风险地址" | "This address is on a sanctions list" / "First time sending here" | F4 |
| 授权盘点回收 | "AI 授权盘点" | "3 apps can spend your tokens" + Revoke | F17 |
| 域名信誉 | "AI 域名校验" | "This domain looks like uniswap.org but isn't" | F15 |
| 合约基础检查 | "AI 风险分 72/100" | 具体事实陈述："Ownership renounced · LP unlocks in 3 days" | C2、E5 |

数据源仍用 GoPlus（$199~799/月）+ 交易模拟。差别只在**呈现方式**：不给分数、不给品牌，只陈述具体事实，让用户自己判断。

### 高风险合约拦截怎么处理

E5 的高风险状态（原 E6 拦截条）和 E7（分析弹层）**保留**，但改为事实陈述：

- 原：`⚠️ AI 检测到高风险函数 · 风险分 23/100`
- 改：`⚠️ This contract can mint unlimited tokens and pause selling`

**仍然不渲染购买入口**——这条纪律不能松。理由不是 AI 判断，而是合约里客观存在 hidden mint 和 pausable 函数，这是可验证的事实。
