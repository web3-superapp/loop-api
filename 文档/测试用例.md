## 一、怎么用这份文档

### 优先级

| 级别 | 含义 | 用法 |
|---|---|---|
| **P0** | 失败即阻塞交付。涉及资金安全、私钥、核心闭环 | 每次构建必跑。**AI 写完就要跑，不等人工审核** |
| **P1** | 失败影响主要功能，但不致命 | 每周五出口检查必跑 |
| **P2** | 体验与边界问题 | 第 6 周加固期跑 |

### 执行方式

| 标记 | 含义 |
|---|---|
| **[自动]** | 可写成自动化测试，AI 应同时产出测试代码 |
| **[真机]** | 必须真机手测，模拟器结果不可信 |
| **[testnet]** | 需在测试网实际执行，不接受 mock |
| **[复算]** | 人工必须独立算一遍数值，不接受"AI 说验证过了" |

> **关于 [复算]**：这是这份用例里最重要的标记。AI 生成的金额计算代码经常"看起来对但边界错"。凡标 [复算] 的用例，审核人要拿计算器或另写一段独立脚本算出期望值，再对比程序输出。

### 2.4 Perp 风险计算（对应 D3、D5、D8）

| # | 用例 | 步骤 | 期望 | 标记 |
|---|---|---|---|---|
| TC-D01 | 强平价计算正确 | 10x 杠杆开多 ETH | **人工独立复算强平价**，与程序显示一致（误差在 tick 内） | [复算][testnet] |
| TC-D02 | 保证金率正确 | 持仓后查 D8 | 账户权益 / 已用保证金 / 维持保证金率三个数字自洽且与官方一致 | [复算][testnet] |
| TC-D03 | 未实现盈亏正确 | 开仓后价格变动 | 盈亏 = (标记价 - 开仓价) × 数量 × 方向，人工复算一致 | [复算][testnet] |
| TC-D04 | 下单精度符合规则 | 提交非法精度的数量/价格 | 客户端提前拦截并提示，不发出必然被拒的请求 | [自动][testnet] |
| TC-D05 | 濒临强平有预警 | 保证金率降到危险区 | D8 显著预警，不是静默 | [testnet] |
| TC-D06 | 行情断线不显示陈旧盈亏 | 断网 30 秒后看持仓 | **明确标注数据已过期**，不显示看似实时的旧数字 | [真机] |

> **TC-D01~D03 是整份用例里最重要的三条。** 这三个数字错了，用户会真实亏钱并且会认为是产品欺骗。审核时必须自己算。

## 三、核心闭环端到端用例（P0，共 6 条）

这是产品的立命之本——原方案的验收标准是"新用户从群聊里一张 Token 卡出发，不离开 App、≤3 次跳转完成 查看行情 → 风险判断 → 买入"。

| # | 用例 | 路径 | 期望 | 标记 |
|---|---|---|---|---|
| TC-X10 | **主闭环：聊天 → 交易** | 群聊 Token 卡 → Buy → Swap → 确认 → 回 Wallet 看持仓 | 全程不离开 App；**跳转 ≤3 次**；持仓正确增加 | [testnet][真机] |
| TC-X11 | 反向闭环：行情 → 社区 | Token 详情 → "进入讨论群" → 群聊 | 能看到该 Token 的讨论，且群内卡片与详情页数据一致 | [真机] |
| TC-X12 | 语音房内交易 | 入语音房 → 房内看到 Token 卡 → Buy → 完成 | **不退出语音房**即可完成买入；音频不中断 | [testnet][真机] |
| TC-X13 | 高风险合约阻断闭环 | 群聊出现高风险合约 | **不渲染购买入口**；只给"查看分析"；分析页列出具体风险项 | [自动] |
| TC-X14 | 三 Tab 互调矩阵 | 从 Market/Chat/Wallet 各自出发调另两个能力 | 页面清单第三章的互调矩阵每格都通 | [真机] |
| TC-X15 | 现货 ↔ Perp 划转闭环 | Wallet 现货 → 划转到 Perp → 开仓 → 平仓 → 划回 | 资金全程可追踪，两侧余额自洽 | [testnet][复算] |

先自动化这四类（投入约 3~4 人日，回报最大）：
