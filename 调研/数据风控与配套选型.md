### 2.2 三个关键问题的结论

**① 交易前模拟用谁？→ Blockaid（主）+ Alchemy Simulate（兜底），不用 Tenderly**

- **Tenderly 排除的理由不是价格而是覆盖**：Tenderly 只支持 EVM，我们首发含 Solana，用它会导致两套逻辑。
- **Blockaid** 是 Phantom 的供应商，EVM + Solana 双覆盖，且直接返回 `benign/warning/malicious` 判定 — 这正是「AI 安全层」需要的输入，不需要我们自己解析 trace。定价未公开，**必须在选型阶段就发询价**。
- **成本量级**：Blockaid/Blowfish 均未公开价格。按同类 usage-based 安全 API 的市场区间，**预算按 $500~2,000/月（初期）、$3,000~8,000/月（10 万 DAU）预留，但需询价确认**。这是本报告最大的成本不确定项。
- Alchemy Simulate 已含在 CU 里，作为 Blockaid 不可用时的降级路径。

**② AML / 制裁筛查是不是合规必需？→ 是，但最便宜方案免费**

- **必需性判定**：只要 App 里有法币出入金（即使是接 MoonPay/Transak 的 widget），或者要上 App Store / Google Play 的受管辖地区，制裁名单筛查就是**事实上的必需**。Google Play 2026-01-28 生效的新政要求上传各国牌照证明；Apple 3.1.5 要求交易功能仅在持牌地区可用。
- **但注意责任边界**：接 Transak/MoonPay 这类 widget 时，**KYC/AML 的合规主体是它们，不是 LOOP**。LOOP 需要做的只是「不给已被制裁的地址提供服务」这一层perimeter blocking。
- **最便宜的合规方案 = Chainalysis 免费制裁 API（$0）**。覆盖 US OFAC + EU + UN 名单，REST 直连，无需商用授权，钱包/dApp 广泛在用。
- **它的边界要写进设计文档**：只给是/否二元结果，**无风险评分、无审计留痕、无历史筛查记录、无批量处理**。对 EU 受监管 CASP 框架不够用。所以：**Phase 1 用免费 API 顶住；一旦自己申请牌照或被通道方要求，就必须升级到 TRM/Elliptic（$40k+/年）**。这个升级点要提前写进财务模型。

**③ 能不能只用一两家？→ 可以压到「GoPlus + Blockaid + Chainalysis 免费」三家，不能更少**

三家各自不可替代：

- **GoPlus** = 代币静态风险（买之前判断这个币能不能碰）。这块 Blockaid 不做。
- **Blockaid** = 交易动态模拟（签之前判断这笔交易会不会被盗）。这块 GoPlus 不做。
- **Chainalysis 免费 API** = 地址制裁命中（合规红线）。前两家都不做，且它免费。

**不要拼第四家**。Honeypot.is 可作为 GoPlus 蜜罐结果的免费交叉验证（提升 AI 安全层置信度描述），但不作为独立依赖 — 它无 SLA。

### 2.3 误报问题（产品设计必须应对）

公开评测数据缺失，但两家供应商的已知弱点是明确的：

- **Blockaid**：会偶发把「合法的新合约」标为可疑 —— 这对 Launchpad 场景（全是新合约）是直接冲突。
- **Blowfish**：复杂多指令交易（Solana 常见）模拟会失败。
- **共性**：都无法覆盖社工诈骗。

### 3.2 返佣结论（这是收入来源，重点）

**能分成，且是两种不同机制，要分清：**

1. **Transak = 加价型（markup）**。你在 Transak 基础费之上加最高 **5%** 的 partner fee，加多少你自己定，全额归你。**上限最高、控制权最大**，但费率直接体现在用户看到的报价里，加太多会掉转化。
2. **MoonPay = 分成型（affiliate fee）**。区间 **0.5%~1.25%/单**，由 MoonPay 侧配置，可与 Partner Success Manager 谈。**上限低但对用户报价影响小**。月流水超 $1M 后可另谈 revenue share。

**收入量级估算**（假设 10 万 DAU、1% 用户每月出入金一次、单笔 $200）：

- 月流水 ≈ 100,000 × 1% × $200 = **$200,000**
- 走 Transak 加 1.5% partner fee → **$3,000/月**
- 走 MoonPay 取 1.25% affiliate fee → **$2,500/月**
- 结论：**出入金返佣在 10 万 DAU 量级约 $2,500~3,000/月，刚好能覆盖第一章的数据成本**。这条收入线值得在 Phase 1 就把埋点和 partner 账号准备好。

**推荐：Transak（主）+ MoonPay（备）双接**

- 双接的理由不是冗余，是**覆盖与转化**：单家的支付方式在具体国家常有缺口，双接可按用户地区路由到成功率高的那家。
- Transak 做主，因为 partner fee 上限 5% 且完全自主。
- MoonPay 做备，因为全美 50 州持牌 + 160 国覆盖是最广的。
- **亚洲下沉市场（印尼/菲律宾/越南/印度）单独接 Alchemy Pay**，它的本地支付方式（QRIS/UPI/VietQR）是 Transak/MoonPay 覆盖不到的，如果 LOOP 的目标用户在东南亚，这家必接。

**LOOP 自己是否需要持牌？→ Phase 2 接 widget 不需要**

接 widget/SDK 模式时，KYC、AML、资金牌照全部由通道方承担，LOOP 只是导流方。**但一旦 LOOP 自己托管资金、自己做撮合、或把出入金做成「看起来是 LOOP 提供的服务」，责任就转移过来了**。设计上必须保持通道方品牌可见。

**中国用户：全部不支持。** 没有任何一家主流合规通道支持中国大陆用户或 CNY。这是硬约束，产品上不要为中国用户设计出入金路径。

### 3.3 App Store 影响

- 接第三方 widget 的出入金**本身不必然触发 3.1.5 拒审**，但会让 App 从「非托管钱包」被重新归类为「涉及法币兑换」，进而被要求提供牌照材料或法律意见书（多个来源提到 Apple 对「非托管钱包 + 加了法币 on-ramp」会额外索要合规材料）。
- **实操建议**：iOS 首个版本**先不放出入金**，用非托管钱包 + 只读行情过审；出入金在 Phase 2 通过**服务端开关按地区灰度开启**，且优先在 Web/PWA 上线。

### 4.1 AI 成本测算：每天 10 万次风险解读

**关键前提：风险解读是「固定系统提示 + 短变量」的典型缓存场景。** 单次假设 1,500 输入 token（其中 1,200 为可缓存的系统提示 + 风控字段模板，300 为该代币的变量）+ 300 输出 token。

| 方案 | 单次成本 | **月成本（10 万次/天 × 30 天 = 300 万次）** |
|---|---|---|
| Haiku 4.5，**无优化** | 1,500×$1/1M + 300×$5/1M = $0.0030 | **$9,000** |
| Haiku 4.5 + **prompt caching**（1,200 token 命中缓存 @$0.10，300 新输入 @$1.00） | $0.00012 + $0.0003 + $0.0015 = $0.00192 | **$5,760** |
| Haiku 4.5 + **caching + Batch API 五折**（风险解读可异步，非实时阻塞） | ≈ $0.00096 | **$2,880** |
| GPT-5 mini + caching | 约 Haiku 的 40% | **≈ $2,300** |
| **推荐：分层策略** | 见下 | **≈ $600~1,200** |

**分层策略（真正的省钱办法，把 90% 的调用消掉）**：

1. **结果缓存**：同一个代币的风险解读缓存 6~24 小时。热门代币被反复查看，**同币去重后实际唯一调用量通常只剩 5%~10%**。10 万次/天 → 实际 LLM 调用 5,000~10,000 次/天。
2. **规则前置**：GoPlus 返回的结构化字段（蜜罐 true/false、mint 权限未放弃等）**直接用模板文案渲染，不过 LLM**。只有需要综合判断和自然语言解释时才调 LLM。
3. **模型分层**：常规解读走 Haiku，只有用户主动点「深度分析」才走 Sonnet 级别。

按分层后 8,000 次/天有效调用 × $0.00192 × 30 ≈ **$460/月**，加上深度分析等长尾，**预算 $600~1,200/月足够**。

**注意团队自有中转站的账**：走自家 1Token 中转不会让上游 token 成本消失，只是把利润留在自己体内。**做成本模型时按上游真实价算，不要按对外售价算**，否则会低估。

| **非托管钱包明确豁免** | 非托管钱包**不在**该政策适用范围内 | ✅ **这是 LOOP 最重要的护城河：坚持非托管架构（Privy 嵌入式钱包属此类），就能避开绝大部分牌照要求** |
| **适用范围** | 交易所、软件钱包（托管）、broker/交易助手、DeFi/staking/lending、可购买或交换 NFT 的市场 | ⚠️ **「交易助手」和「DeFi」措辞宽泛，Launchpad + Swap 可能被归入** |
| **分地区牌照证明** | 需上传：加拿大 FINTRAC、德国 BaFin/MiCA、**EU 自 2026-07-01 起只认 MiCA CASP**、韩国 KoFIU VASP、美国 FinCEN MSB + 各州 MTL、英国 FCA、日本 FSA、香港 SFC Type 1&7、UAE、泰国 SEC、南非 FSCA 等 | 无牌照的地区**在 Play Console 里从分发目标中移除**，这是最快的合规办法 |
| **韩国 2026-01-28 起完全封锁** | 未在 KoFIU 注册的境外交易所/钱包 App 全部下架，已装的不再更新 | 韩国先不做分发目标 |
| **禁止「赚钱」叙事** | 不得宣传「making money」「稳定收益」「高收益」 | ⚠️ **代币激励 / 空投 / 积分体系的文案是雷区**，不能写成收益承诺 |
| **禁止 NFT 抽奖 / 盲盒 / gacha** | 价值不确定的博彩类元素**基本无法通过审核** | ⚠️ 若 Launchpad 含抽签/盲盒机制，必须去掉 |
| **必须填 Financial Features Declaration** | 勾选「crypto wallet/exchange/NFT」会触发逐项披露与牌照上传 | 如实填写，勾选前先确定功能边界 |
| **禁止设备端挖矿** | 远程挖矿可能允许 | 不涉及 |
| **允许的** | 区块链教育内容、展示链上数据（价格、图表、地址）、信息性展示 NFT | 行情 / Chat / Profile 这几个 Tab 是安全区 |

### 6.3 关键判断：LOOP 的六个 Tab 风险分级

| Tab | 风险 | 处理 |
|---|---|---|
| Home / Market（行情） | 🟢 低 | 「展示链上数据」明确允许 |
| Chat | 🟢 低 | 注意 UGC 内容审核（另一条独立的审核要求） |
| Profile | 🟢 低 | 注意积分/激励文案不写成收益承诺 |
| Wallet（非托管） | 🟡 中 | 组织账号 + Secure Enclave + 测试钱包，Play 侧豁免 |
| Swap（在 Wallet 内） | 🔴 **高** | iOS 首版建议移除或跳转 Web；Android 视地区灰度 |
| **Launchpad** | 🔴 **最高** | **iOS 首版只做信息展示，不做认购**；去掉一切抽签/盲盒机制；文案禁止收益暗示 |

### 6.4 退路

| 退路 | 可用性 | 说明 |
|---|---|---|
| **PWA** | ✅ **主退路** | Swap / Launchpad 的完整功能放 Web/PWA，App 内跳转。不受商店政策约束。**这也是为什么第一章要求 Web 优先** |
| **TestFlight** | ⚠️ 内测限定 | 最多 1 万人，仍需过 Beta App Review（比正式审核松，但不能长期当分发渠道） |
| **APK 侧载 / 第三方商店** | ⚠️ Android 可行 | 官网直下 APK 是币圈常规做法；转化率低于 Play，但不受政策约束 |
| **网页版直接访问** | ✅ | Google Play 韩国封锁的案例里明确说明「用户仍可通过网站访问服务」 |

**策略结论**：**双轨制**。App Store / Play 上架一个「合规瘦身版」（行情 + 非托管钱包 + Chat + 只读 Launchpad），完整功能走 PWA。这不是妥协，是这个品类的标准做法。

## 第七章：遗留待确认问题

**必须在选型定稿前解决（阻塞性）**

1. **Blockaid / Blowfish 报价** — 两家都不公开定价，这是成本表里最大的空洞（初期 $500 / 10 万 DAU $3,000 均为占位估算）。**行动：立刻同时向两家发询价，问清计费维度（按调用次数还是 MAU）、Solana 是否同价、有无 startup 折扣。** 若报价过高，降级方案是「Alchemy Simulate（EVM）+ GoPlus 代币风险」，但会失去 Solana 的交易模拟。
2. **Nansen 包月价** — 按次 $0.05 在 10 万 DAU 下会失控（若每用户每天触发 2 次 Smart Money 查询就是 $300/天）。**需谈包月上限，或把 Smart Money 做成付费会员专属功能。**
3. **CoinGecko 实际档位与 credit 消耗** — 第三方来源对 Analyst/Lite/Pro 的价格口径不一（$103.20/$129、$399.20/$499、$999）。**需登录官网确认真实档位**，并按我们的端点组合实测 credit 消耗（WebSocket 按 0.1 credit/条计，长连接下消耗需要实测）。
4. **CoinMarketCap 的「10 万用户上限」** — 其商用授权写明「1 个产品 + 10 万用户」。若考虑用 CMC，这条正好卡在我们的目标量级上，**需确认是 MAU 还是累计注册用户**。这也是不选 CMC 的主要原因。

**Phase 2 前需确认**

5. **出入金 partner 账号与 KYB 周期** — Transak 和 MoonPay 都要过 KYB 审核。**需确认 KYB 需要什么公司材料、审核周期多久**，避免 Phase 2 卡在合规审核上。
6. **目标市场决定第三家通道** — 若东南亚是重点市场，Alchemy Pay 必接（QRIS/UPI/VietQR 是 Transak/MoonPay 覆盖不到的）。**需产品侧先给出目标国家优先级。**
7. **Banxa / Mercuryo / Coinbase Onramp / Stripe 的 partner fee** — 均未公开，若要横向比返佣需逐家询价。目前判断 Transak（5% 上限）已是最优，不必急。

**架构与合规**

8. **缓存网关是唯一必须自己写的组件** — 与「不写核心代码」的原则有张力。**建议明确：这层只做缓存 + 配额 + 聚合，不做业务逻辑**，用现成方案（如 Cloudflare Workers + KV / Redis）把代码量压到最小。
9. **AML 升级触发条件** — Chainalysis 免费 API 只给二元结果、无审计留痕。**需明确：什么条件下必须升级到 TRM/Elliptic（$40k+/年）**？建议触发条件为「自己申请牌照」或「通道方书面要求」。这笔钱要提前进财务模型。
10. **Apple 组织账号 + D-U-N-S** — 有申请周期，**需现在就启动**，否则会阻塞首次提审。
11. **法律意见书预算** — 非托管钱包加了出入金后，Apple/Google 都可能索要律师意见书。**需预留这笔预算（币圈行价通常数千至数万美元，需具体询价）。**
12. **Launchpad 的合规形态** — 这是产品与合规冲突最严重的地方。**需产品侧先定义：iOS 上的 Launchpad 到底是「只读信息流」还是「可参与认购」？** 这个决定直接影响能否上架，应在开发前定，不要做完再改。
